Date: 2026-09-09. The production Worker, the local CLI, and the primary remote agent
host now run the agent channel: relay `lease.release`, one-shot `panel update`,
lifecycle shortcuts, and `panel doctor`. No database migration was required.

## Order and compatibility

The Worker shipped first. An older CLI against the new Worker is unaffected: it sends no
release frame and its lease expires on the existing deadline, exactly as before. A 1.8.0
CLI against an older Worker reports a version mismatch rather than a delivery failure,
which is why clients could not move first. The secondary agent host therefore keeps
working on its older binary until it can be upgraded.

## Verification in production

- A producer connection ticket lists `subscribe`, `lease.claim`, `lease.release`,
  `state.update`. `panel doctor` reports protocol v2 with the release capability, the
  resolved session, the resolved bosses, and a completed relay subscribe.
- A check panel was published, updated three times in seven seconds, and completed.
  Every update was accepted. This is the case that previously failed: before the change,
  a second one-shot update inside the 45-second lease window was refused with
  `lease_conflict`.
- After the third update the checkpoint reported three observations and a null lease
  expiry, so the lease is released when a command exits rather than left to time out.
- Completion used the shortcut command with no hand-written version fields, and the
  panel reached `completed`.
- Republishing the same document after completion exits non-zero and names `--run-id`.
- The seven retained panels list and read normally.

## Defects found by running the deployed build

Both were client-side; neither required a Worker change, and both were fixed and
reinstalled the same day.

- `panel doctor` exited 1 for an agent with more than one boss. That is the ordinary
  case for this account, so the pre-flight was unusable exactly where it was wanted.
  Doctor now reports every resolved boss and checks panel membership against the set.
  Publication still requires an explicit target when several bosses resolve.
- The publish `sessionId` fill sat after the validation that required the field, so it
  could never run and `panel validate` rejected any document omitting it. Both commands
  now fill the session identifier before validating, through one shared step.

## Recovery

The previous Worker version was `ebcdd6ba-8a9a-4ee4-8152-d077e7153e19`. Local and remote
CLI backups were written beside each installed binary before replacement. Rolling the
Worker back also requires reverting any 1.8.0 producer to the older binary, because a
1.8.0 producer reports a version mismatch against a Worker without `lease.release`.
