# Handoff — bound table rows, wall render churn, per-box cards, 2026-09-15

Three changes merged today: two in this repository (both native clients rebuilt and installed,
no server change) and one in the build-box tooling that turns every build box into a HiBoss
agent with its own live card. Two performance follow-ups are measured and left open.

## What is true now

**A Table binds its rows.** The catalog always accepted `Table.rowsBinding`, but both native
renderers read only literal `rows`, so a live table never updated and producers fell back to
`Metric` elements holding sentences, which the detail draws in the large bold metric font. The
shared leaf resolver (`HibossKit/Sources/HibossKit/PanelWebLeaf.swift`,
`resolvedWebLeafDefinition`) now turns a resolved `rowsBinding` into `rows`; literal rows keep
precedence; rows that are not objects are dropped; every cell is a text node, never markup. The
`e2e-test-run` example binds its rows through `/task/tests`, and the guide's element table
names every prop that binds (`Metric.value`, `Text.text`, `Progress.value`, chart `values`,
`Table.rowsBinding`; inputs through `$bindState`) and reserves `Metric` for a number or a short
word. Merge 79e19ee.

**The wall no longer re-renders every second.** `PanelsModel.now` was `@Published` and ticked
each second, and the iOS home screen wrapped its whole scroll view in a one-second
`TimelineView`, so every tile re-evaluated once (macOS) or twice (iOS) per second. The clock is
now a plain property; the model publishes only when a wall signature (visible tile IDs plus
per-tile pending questionnaire counts) changes; the one-second timeline is scoped to the
attention rows, to `PanelFreshnessLabel`, and to the questionnaire editor's expiry controls;
`PanelTilePreview` builds its `PanelDashboardContent` once per render behind an `Equatable`
boundary on store identity, spec and summary. Measured: macOS idle on the dashboard with six live
cards 25.1% → 14.1% CPU over 40 s, main-thread SwiftUI view-graph share of samples ~36% → ~1%;
simulator with five tiles of 60-point series, wall/card body evaluations per second 0.96/4.8 → 0
and summary constructions 22.3/s → 2.5/s. Charts themselves were already pruned by SwiftUI
before the change. Merge a75b0b6.

**Every build box is a HiBoss agent with a card.** The build-box tool's `ensure` step now ships
the Linux CLI, a stdlib producer script and the box's key, and starts the producer under a
self-restarting loop as the build user (the boxes are containers under `tini`; `systemctl` is
installed but cannot operate). Each card shows CPU % with a 60-point series, load, memory and
disk with real-denominator progress, uptime and the build lock, updates every 60 s, renews its
seven-day visibility every 6 h, and on reboot completes the old card and publishes a new run. A
box without a key file and without a pre-existing root config gets the files and no daemon.
Keys are seeded from the operator's machine so a VM reset restores the identity; two identities
were migrated from a root-owned config, two were enrolled through the join flow
(`env USER=<name> hiboss init <server>` and a boss approval). The operator-side fleet card draws
per-box rows as a bound Table and republishes itself when its definition changes.

## Why the detail was a wall of bold text

The producer tried a bound table, saw nothing render, recorded "only Metric and chart values
bind" as a comment, and emitted one Metric per box whose value was a sentence. Each layer was
individually correct — schema, example, renderer — and no layer exercised the feature end to
end. A capability that no example shows and no renderer test draws does not exist in practice;
the empirical limit then becomes policy. The fix is the same as on 09-13: walk the feature from
schema to pixels before recording a limit, and ship an example that binds every bindable prop.

## Open

- **The 10-second reconcile republishes every tile.** `PanelsModel.startClock()` calls `load()`
  every 10 s when not fetching; the fetched list replaces `tiles`, which re-renders the whole
  wall. This is the remaining idle cost on macOS (spikes to ~40% every few seconds). Diff the
  fetched metadata against the current tiles and publish only on change.
- **The detail remounts a chart on every state update.** `PanelWebLeafSlot` re-resolves the
  definition on each store change; a changed chart or table resets `mountSent` and sends the
  whole definition to the web leaf, which rebuilds the plot or table DOM. Unchanged leaves do
  not remount. A `data-update` bridge message with node reuse and cross-platform regression
  tests is a separate one-to-two-day change.
- Carried over from 2026-09-13: the y-domain of line charts includes zero, so a narrow series
  reads as a flat line; questionnaire submission from iOS still reports the generic
  token-rejected text.
- The guide is embedded in the CLI; the installed copy on the operator's machine was updated by
  hand today, and the next CLI release carries it.

## Operating notes

- `hiboss panel doctor` and `publish` refuse without a session file; a headless producer runs
  `hiboss hook session-start` first, with `HIBOSS_PROJECT` naming the project it should group
  under.
- `hiboss agent create` requires an admin agent; a non-admin enrols a new host through the join
  flow. A lost key cannot be re-minted under the same name, so keep every headless key seeded
  off the host.
- A retry chain in the dispatcher compresses long prompts; the third round's feedback was lost
  and the agent returned DONE with no change. After two corrections, dispatch a fresh short brief
  on the same branch instead.
